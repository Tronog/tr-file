# Overview (FIXES)

# Section 1
- Bugs in the existing code:
  - A symlink to a folder opens as a file preview instead of navigating into it (file-browser.feature.ts:172).
  - Memory leak: cached images are never freed. The function that frees them is never called, so every previewed image (up to 32 MiB each) stays in memory for the whole session.
  - On the desktop, reading, uploading and downloading all load the whole file into memory, sometimes twice.
  - Download errors only go to the browser console, and downloads never appear in the Transfers panel.
  - Listing a folder checks each entry one after another, which will be slow for big folders. Nothing in the UI renders only the visible rows either.
  - Files are shown as text unless their extension is on a list of binary types, so .docx, .sqlite and similar files render as garbage.
  - Sorting puts file10 before file2.

# Section 2
- Security, which matters before adding delete and move:
  - The server deployment has no login at all.
    - implement simple username password, but for desktop should be optional (disabled by default on desktop)
  - The upload endpoint can be triggered by any website a user visits (cross-site request forgery).
  - The desktop app still serves the full, unprotected API on a local port, even though its own window no longer uses it. Any local program, or a web page that finds the port, could read and write files.

# Section 3
- Components built but never connected: the right-click menu component is never used, the menu bar has no handler for clicks, the activity bar's Search and Bookmarks buttons do nothing, and the Places pane is empty.

# Section 4
- Decisions to make before building the missing operations:
  - Whether to keep one confined root folder or support several roots and absolute paths.
  - One shared way to run long jobs and push progress to the UI, which file watching can reuse.
  - A single command table that the menus, right-click menus, command palette and shortcuts all read from.


# Section 5
Missing: things every file manager has

- Rename (F2), New Folder, New File. Nothing exists in the backend, the bridge or the UI.
- Right-click menus. There are none at all: not on entries, blank space, the tree or tabs. UiContextMenu exists but only draws the menu bar and the Settings menu.
- Sorting by column. The header arrow and the "Sorted by Name" label are for show; the order is whatever the backend sends.
- Filter and search. UiSearchField exists but is never turned on, the Search icon does nothing, and there's no recursive search.
- Typing a path into the address bar. The breadcrumbs can't be edited; only the palette's Jump to Folder takes a typed path.
- Back/Forward buttons. The history works, but only through Alt+←/→.
- Opening a file in its default app, or showing it in the OS file manager. There's no shell.openPath or showItemInFolder, so a PDF or .docx can't be opened at all.
- Undo (Ctrl+Z) and permanent delete (Shift+Delete).
- Auto-refresh. Nothing watches the file system; listings refresh by hand or when a job ends.

# Section 6
Most noticeable gaps

1. You can only browse one folder tree. The desktop confines everything to one root: FILES_ROOT if it's set, otherwise your home folder (desktop/src/desktop.config.ts:156). You can't reach other drives, USB sticks or network mounts (/media, /Volumes, D:\), or any path above home. Every real file manager lists drives and devices.
2. Places and Bookmarks are empty. The Places pane has no content (workbench.html:98) and the Bookmarks button in the activity bar does nothing (chrome.feature.ts:191). There are no Home/Desktop/Documents/Downloads shortcuts, no pinned folders and no recent folders.
3. Nothing is remembered between sessions. The only thing stored in localStorage is the list of saved servers. Open tabs, panel layout, folder paths, view mode, sort order, sidebar widths and the hidden-files toggle all reset on every start. The Settings menu only has a disabled "Todo" entry.
4. No link to the OS clipboard or drag and drop out of the app. Copy and paste of files only works inside tr-file. You can't paste files copied in Nautilus or Explorer, and you can't drag a file out to another app (there's no webContents.startDrag).
5. Grid view has no thumbnails. The icon view only ever shows icons; the only <img> in the UI library is in the image viewer.
6. Folders can't be uploaded or downloaded. There's no folder picker or folder drop, and a folder can't be downloaded. There's also no zip or archive support: you can't browse inside an archive, extract it or compress files.
