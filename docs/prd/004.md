## Section 1.3 (file-browser details)
### Section 1.3.1 (file-browser details)
Sort and view type (detail/tree/icon...) is on per folder basis and is stored in local client storage.


### Section 1.3.2 (copy path)
`Copy Path` should copy the full path as string into clipboard.
Ctrl-Shift-C should be the shortcut for it.
Pressing Ctrl-Shift-C twice in a second should copy a UNIX path to clipboard.
That means converting drive to unix directory (`C:\` to `/C/`, or `T:\` to `/T/`) and backslashes to slashes.

## Section 1.4 (paths)
In Windows, paths still start with `/`, like `/C:/Windows`. Make sure it does not start with `/`.

# Section 3 (optimization)
## Section 3.1 (large folders)
We are countering the slowdown or halt when we open folder with milions of files.
When folder has less than 1000 files, behavior stays the same.
When there are more, we need an on-demand behavior that is performed in worker.
It should first get item list with their names. First the 1000 it already got, then the rest, in 10000 item chunks. Update UI every 1 second.
Asynchronously the app gets rest of the data about files in background.
Fetching should be in batches, not per single item.
Update should be once per second until fetch is done.

### Section 3.1.1 (manual refresh)
Polling for updates should not be done on large folders. Manual refresh only.

### Section 3.1.2 (abort)
Listing should abort if user navigates to different folder in this tab.

### Section 3.1.3 (item count in details)
If more than 1000 files, it should show `1000+ items`. If user clicks on `1000+ items`, it calculates.

### Section 3.1.4 (abort)
Pressing `Esc` should abort the listing.
